# 10. 문제 다시 설계하기 — "수준이 너무 낮고 이상해"

## 배경

장 전체 암송(09장)을 넣고 실제로 풀어 본 사용자의 한 줄 평가였습니다.

> "문제 수준이 너무 낮고 이상해."

이어서 요구가 더 분명해졌습니다.

> "노트북으로 풀 때는 입력이 쉬운데 모바일로도 풀 거라서 주관식을 너무 길지는 않게… 객관식 위주로 하되 주관식은 짧게 입력하게 적절히… 많~~~~이 푼 다음에는 길게 입력하는 주관식 문제도 OK. 성경고사 같은 거 좀 검색해서 문제 유형 참고해 봐. 어와나 성경 퀴즈대회 문제 같은 거."

## 1. 진단: 왜 "낮고 이상한가"

잠언 3장으로 만든 문제를 다시 봤습니다.

| 문제 | 오답 | 문제점 |
|---|---|---|
| `여기지 (  )` | 말노라, 말리라, 말니라 | 말이 안 됨 → **한국어만 알면** 맞힘 |
| 정확한 본문 | `여호와는 신뢰하고`, `명철은 의지하지` | 조사만 바꿔 문장이 깨짐 → 바로 보임 |
| 틀린 곳 찾기 | `명령 지키라` | 조사가 빠져 눈에 띔 |
| 다음 절 | `내 재물과`, `너는 범사에서` | 한 글자 비튼 것, 실제로는 헷갈리지 않음 |

**핵심 원인:** 오답이 "문법을 깨는 변형"이었습니다. 좋은 오답은 **기억이 없으면 고를 수 없어야** 합니다. 그런데 이 오답들은 한국어 감각만으로 걸러졌습니다. 이건 암송 실력이 아니라 국어 실력을 잽니다.

반대로 **실제로 헷갈리는 것**은 이런 것들입니다.

```text
네 마음으로 나의 명령을 지키라   ↔  네 마음판에 새기라          (1절 ↔ 3절)
여호와를 경외하며 ↔ 여호와를 신뢰하고 ↔ 여호와를 공경하라        (7절 ↔ 5절 ↔ 9절)
나의 명령을 ↔ 나의 계명을,  신뢰하고 ↔ 의뢰하고                   (비슷한 뜻의 다른 낱말)
```

모두 **문법이 맞고**, 같은 장 안이나 비슷한 번역에서 실제로 나오는 말입니다.

> **시니어의 관점:** 08장에서 "그럴듯한 오답"을 규칙으로 만들었지만, 그때 기준은 "작은 차이"였습니다. 작은 차이와 **그럴듯한** 차이는 다릅니다. 품질 기준을 잘못 세우면 테스트가 전부 통과해도 결과물은 나쁩니다.

## 2. 조사: 성경퀴즈 대회는 어떻게 내나

어와나 공식 규정은 찾지 못해서, 비슷한 해외 대회(나사렛 성경퀴즈)와 국내 교회들의 기출·예상문제, 암송대회 규칙을 참고했습니다.

| 유형 | 출처 | 앱에 옮긴 형태 |
|---|---|---|
| **Finish the Verse**: 첫 몇 어절을 듣고 나머지를 **토씨까지 정확히** | 나사렛 성경퀴즈 | 절 끝까지 쓰기 (4단계) |
| **Quote**: 장절을 주고 본문 전체를 암송 | 나사렛 성경퀴즈 | 여러 절 암송 쓰기 (4단계) |
| 괄호 채우기 | 국내 교회 성경퀴즈 | 빈칸(객관식, 1단계), 빈칸 쓰기(2단계) |
| 짝짓기 (가)(나) | 국내 교회 성경퀴즈 | 짝짓기 (2단계) |
| OX / 틀린 것 고르기 | 국내 교회 성경퀴즈 | OX (1단계), 틀린 곳 찾기 (2단계) |
| 나열형 | 국내 교회 성경퀴즈 | 절 순서·절 안 순서 (1단계) |
| 힌트 1회당 −10점 | 암송대회 규칙 | 초성 힌트를 쓰면 그 답은 단계에 반영 안 함 |
| 화자 맞추기, 일반 상식 | 국내 교회 성경퀴즈 | ✗ 본문 밖 정보가 필요해서 제외 |

## 3. 결정과 트레이드오프

### 오답의 출처

| 방식 | 품질 | 비용·속도 | 본문 외부 전송 |
|---|---|---|---|
| 문법 규칙 변형 (기존) | 낮음 (문장이 깨짐) | 무료·즉시 | 없음 |
| **같은 장의 실제 구절** | 좋음 (항상 문법이 맞고, 실제로 헷갈림) | 무료·즉시 | 없음 |
| **Claude가 미리 만든 변형** | 가장 좋음 (`계명을`, `의뢰하고`) | 본문당 1회, 13절 약 $0.03 | 있음 (내 PC에서 실행) |

사용자 선택은 **둘 다**였습니다. 같은 장 구절이 기본이고, Claude 변형이 있으면 먼저 씁니다. 앱이 실행 중에 AI를 부르지 않는다는 원칙(01장)은 지켜집니다. 생성은 **미리, 한 번** 합니다. 주제 사전을 미리 만든 것과 같은 방식입니다.

### 객관식과 쓰기의 균형: 단계

| | 객관식만 | 쓰기만 | **단계별로** |
|---|---|---|---|
| 모바일 | 편함 | 힘듦 | 처음엔 편하고, 익숙해질수록 쓰기 |
| 훈련 | 알아보기(재인)만 | 떠올리기(회상)부터, 초보에게 벽 | 재인 → 회상 순서 |
| 요구 반영 | "많이 푼 다음 길게"를 못 함 | "주관식 짧게"와 충돌 | ✅ |

| 단계 | 오르는 조건 | 새 문제 | 입력 |
|---|---|---|---|
| 1 알아보기 | 처음 | 빈칸 · OX · 정확한 본문 · 이어지는 말 · 첫마디 · 다음 절 · 절 순서 · 절 안 순서 | 없음 |
| 2 구별하기 | 5번 정답 | 틀린 곳 찾기 · 짝짓기 · 단어 놓기 · 빈칸 쓰기 | 1~2어절 |
| 3 떠올리기 | 10번 이상 풀어 80% | 이어 쓰기 | 3~5어절 |
| 4 암송하기 | 쓰기 3번 연속 정답 | 절 끝까지 쓰기 · 여러 절 암송 | 긴 입력 |

단계는 **절마다** 둡니다. 장 전체를 외울 때 1절은 이미 4단계인데 12절은 1단계일 수 있기 때문입니다. 문제를 고를 때 그 절의 단계 이하만 내고, **새로 열린 단계 문제를 가장 많이**(가중치 ×3), 바로 아래 단계는 ×2, 더 아래는 ×1로 냅니다.

## 4. 코드로 보기

### ① 본문을 "오답 재료"로

```ts
// src/lib/memorize.ts
interface Word { i: number; token: string; core: string; tail: string; kind: "p" | "e" | ""; group: string }
// 지키라 → { tail: "라", kind: "e" (어미), group: "final" }
// 마음으로 → { tail: "으로", kind: "p" (조사), group: "dir" }
```

08장에서 만든 조사·어미 분석(`parse`)을 **오답을 만드는 데**가 아니라 **모양을 비교하는 데** 다시 썼습니다. 같은 분석기라도 용도를 바꾸니 결과가 달라졌습니다.

```ts
const score = (x: Word) =>
  (w.tail && x.tail === w.tail ? 4 : 0) + (w.kind && x.kind === w.kind ? 2 : 0) + (w.group && x.group === w.group ? 1 : 0)
  + (Math.abs(x.core.length - w.core.length) <= 1 ? 1 : 0) - (x.i < 0 ? 1 : 0);
```

결과 (잠언 3장):

```text
… 네 마음으로 나의 명령을 (   )   →  지키라 / 공경하라 / 말라 / 새기라
… 여호와를 (   ) 악을 떠날지어다   →  경외하며 / 매며 / 하며 / 지혜롭게
```

### ② 문장 안에서 바꿀 때는 더 엄격하게 (`strict`)

빈칸 보기는 문장 밖에 따로 서 있어서 조금 달라도 괜찮습니다. 하지만 OX·정확한 본문처럼 **문장 안에 끼워 넣으면** 어색함이 바로 드러납니다.

```text
그리하면 그것이 진리가 장수하여 …     (네가 → 진리가: 같은 '가'지만 말이 안 됨)
```

그래서 문장 안 교체는 **꼬리가 똑같고, 어간이 두 글자 이상**인 것만 허용했습니다. 바꿀 자리도 동사 어미 쪽에 가중치 3, 명사 쪽에 1을 줍니다. 동사 바꾸기(`잊어버리지 → 싫어하지`)가 명사 바꾸기(`아비가 → 창고가`)보다 훨씬 자연스럽기 때문입니다.

### ③ 구절 바꾸기: 양 끝 모양이 같을 때만

```ts
// Same shape at both ends: 네 마음으로 나의 명령을 지키라 ↔ 네 마음판에 새기라
const ends = last.tail ? ol.tail === last.tail && ol.kind === last.kind : norm(ol.core) === norm(last.core);
return ends && (norm(o.words[0]) === norm(c.words[0]) || (!!first.tail && of.tail === first.tail && of.kind === first.kind));
```

처음에는 "끝 어절 모양만 같으면"이었는데, `가득히 이것이 네 몸에`처럼 이상한 문장이 나왔습니다. 꼬리 없는 어절(`가득히`, `징계함`)은 모양에 대해 아무것도 알려 주지 않는데도 "같다"고 판정됐기 때문입니다. **비교할 정보가 없는 것끼리의 일치는 일치가 아닙니다.**

```ts
// from: 원문 절에 있는 연속된 어절을 글자 하나 바꾸지 말고 그대로 복사
export function toVariants(vs: VerseLine[], raw: { verse: number; from: string; to: string }[]): Variant[] {
  // from이 그 절에 정말 있는 어절 묶음인지 확인 → 어절 위치(start, end)로 변환, 같은 것은 버림
}
```

LLM 출력은 **위치(몇 번째 어절)**로 받지 않고 **원문 복사(from)**로 받은 뒤 코드가 위치를 찾습니다. LLM은 숫자 세기보다 베껴 쓰기를 훨씬 정확하게 하기 때문입니다. 원문과 맞지 않는 것은 버립니다.

실제 한 번 실행한 결과입니다 (잠언 3장 13절, 51개 중 51개 채택, 약 $0.026):

```text
나의 명령을 → 나의 계명을        신뢰하고 → 의뢰하고        지도하시리라 → 인도하시리라
꾸지람을 → 책망을                인자와 진리가 → 진리와 인자가
지혜를 얻은 자와 명철을 얻은 자는 → 명철을 얻은 자와 지혜를 얻은 자는
```

`의뢰하고`, `인도하시리라`는 다른 한국어 번역본에서 실제로 쓰는 표현입니다. 여러 번역을 읽어 본 사람이 정말 헷갈리는 지점입니다.

### ⑤ 단계 규칙은 두 곳에, 같은 테스트로

```ts
export function nextProgress(cur, ok, recall) {
```

화면은 즉시 반응하도록 브라우저에서 계산하고, DB는 `record_memory_result`가 **행을 잠근 뒤**(`select … for update`) 같은 규칙으로 계산합니다. 노트북과 휴대폰에서 동시에 풀어도 숫자가 덮어써지지 않습니다. 양쪽을 같은 시나리오로 확인했습니다(Vitest, PGlite).

## 겪은 문제

### 1. 보기 하나가 다른 보기의 앞부분

```text
… 네 마음판에 새기라 다음은?   * 그리하면 네가   /   그리하면 네
```

다음 절 문제에서 다른 절의 첫마디를 정답과 **같은 어절 수**로 잘랐기 때문입니다. 09장에서 정답은 구별되게 늘렸지만, 오답에는 같은 규칙을 적용하지 않았습니다. 이제는 각 절을 **자기만의 구별 길이**로 자르고, 한쪽이 다른 쪽의 앞부분이면 버립니다.

### 2. 테스트를 고칠 것인가, 기대를 고칠 것인가

재설계 후 기존 테스트 두 개가 실패했습니다.
- "보기는 3개 이상" → OX는 2개. **명세가 바뀌었으니** 테스트를 고쳤습니다.
- "첫 버튼을 누르면 정답 표시가 하나" → 순서 문제에는 정답 표시가 없음. 화면 동작은 맞았고, 테스트가 문제 유형을 가정하고 있었습니다.

실패한 테스트를 "통과하게 고치기" 전에, **무엇이 바뀌었고 무엇이 맞는지**를 먼저 말로 정했습니다.

## 배운 것

**주니어 관점**
- 좋은 객관식 오답의 기준: **기억이 없으면 못 고른다.** 문법이 틀린 오답은 국어 시험이 된다.
- 기존 대회와 시험의 문제 유형은 오랜 경험이 쌓인 설계다. 처음부터 만들기 전에 찾아본다.
- LLM에게 위치를 묻지 말고 원문을 베끼게 한 뒤, 위치는 코드가 찾는다.

**시니어 관점**
- 사용자의 "이상해"는 버그 리포트가 아니라 **품질 기준이 틀렸다는 신호**일 수 있다. 개별 사례를 고치기 전에 기준(작은 차이 → 그럴듯한 차이)을 다시 세운다.
- 같은 분석기도 **생성용**에서 **비교용**으로 용도를 바꾸면 약점이 강점이 된다.
- 난이도는 하나의 값이 아니라 **사용자의 진행**에 따라 열리는 것이다. 단위(장 전체가 아니라 절)를 잘 고르면 진행이 정확해진다.
- 학습 규칙(힌트 감점)은 점수가 아니라 **진행에 반영**할 때 의미가 있다.
